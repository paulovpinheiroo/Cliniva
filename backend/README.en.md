# Clíniva — Backend API

REST API for the Clíniva aesthetic-clinic management system. Handles
**clients**, **services**, **stock items** and **appointments**
(schedule + services + consumed items).

> Portuguese version: [`README.md`](./README.md)

## Stack

| Layer | Technology |
|-------|------------|
| Language | Java 21 |
| Framework | Spring Boot 4.1 |
| Persistence | Spring Data JPA + Hibernate, PostgreSQL |
| Build | Maven 3.9+ |
| Validation | Bean Validation (`jakarta.validation`) |
| Tests | JUnit 5 + Mockito (in-memory H2) |
| Extras | Lombok, spring-boot-devtools |

## Project structure

Code is organized **by domain aggregate**, not by technical layer:

```
src/main/java/com/cliniva/
├── ClinivaApplication.java       Spring Boot bootstrap
├── cliente/                      Client domain
│   ├── Cliente.java              JPA entity
│   ├── ClienteRepository.java    Spring Data interface
│   ├── ClienteService.java       Business rules
│   ├── ClienteController.java    REST endpoints
│   └── dtos/                     Request/response records
├── servico/                      Service domain (catalogue)
├── item/                         Item domain (stock)
├── atendimento/                  Appointment domain (schedule)
│   ├── enums/StatusAtendimento.java
│   └── model/                    Atendimento, AtendimentoServico, AtendimentoItem
└── exception/                    Global error handling + domain exceptions
```

### Conventions

- **Domain packages**: each domain owns its `Entity`, `Repository`,
  `Service`, `Controller` and `dtos/`.
- **DTO records**: inputs (`Create*/Update*RequestDTO`) and outputs
  (`*ResponseDTO`) never leak entities to the wire.
- **`UUID` ids**, generated by the application.
- **`BigDecimal`** for money and quantities.

## Requirements

- Java 21
- Maven 3.9+
- PostgreSQL on `localhost:5432`

## Database

Create role + database once:

```bash
sudo -u postgres psql -c "CREATE ROLE cliniva LOGIN PASSWORD 'cliniva';"
sudo -u postgres psql -c "CREATE DATABASE cliniva OWNER cliniva;"
```

Tables are created/updated automatically by Hibernate
(`spring.jpa.hibernate.ddl-auto=update`).

### Configuration (environment variables)

| Variable | Default |
|----------|---------|
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://localhost:5432/cliniva` |
| `SPRING_DATASOURCE_USER` | `cliniva` |
| `SPRING_DATASOURCE_PASSWORD` | `cliniva` |

## API reference

All routes are prefixed with `/api`. JSON in/out.

### Clients — `/api/clientes`

| Method | Route | Description |
|--------|-------|-------------|
| `GET` | `/api/clientes` | List (optional `?nome=`) |
| `GET` | `/api/clientes/{id}` | Find by id |
| `POST` | `/api/clientes` | Create |
| `PUT` | `/api/clientes/{id}` | Update |
| `DELETE` | `/api/clientes/{id}` | Delete (409 if referenced by appointments) |

**`POST` / `PUT` body:**

```json
{
  "nome": "Maria Silva",
  "email": "maria@example.com",
  "telefone": "(11) 91234-5678"
}
```

Validation: `nome` and `telefone` required (≤120 and ≤20 chars); `email`
must be a valid e-mail if provided (≤120).

**Response (`GET /{id}` and list):**

```json
{ "id": "0b6f...", "nome": "Maria Silva", "email": "maria@example.com", "telefone": "(11) 91234-5678" }
```

### Services — `/api/servicos`

| Method | Route | Description |
|--------|-------|-------------|
| `GET` | `/api/servicos` | List |
| `GET` | `/api/servicos/{id}` | Find by id |
| `POST` | `/api/servicos` | Create |
| `PUT` | `/api/servicos/{id}` | Update |
| `DELETE` | `/api/servicos/{id}` | Delete (409 if in use) |

**`POST` / `PUT` body:**

```json
{
  "nome": "Limpeza de Pele",
  "descricao": "Limpeza profunda com extração",
  "valor": 150.00
}
```

Validation: `nome` required (≤120); `descricao` ≤500; `valor` required and positive.

### Items (stock) — `/api/items`

| Method | Route | Description |
|--------|-------|-------------|
| `GET` | `/api/items` | List |
| `GET` | `/api/items/{id}` | Find by id |
| `POST` | `/api/items` | Create |
| `PUT` | `/api/items/{id}` | Update |
| `DELETE` | `/api/items/{id}` | Delete (409 if in use) |
| `PATCH` | `/api/items/{id}/estoque` | Stock movement |

**`POST` / `PUT` body:**

```json
{ "nome": "Ácido Hialurônico", "quantidadeEmEstoque": 10 }
```

**`PATCH .../estoque` body:**

```json
{ "tipo": "ENTRADA", "quantidade": 5 }
```

`tipo` ∈ `ENTRADA` | `SAIDA`. A withdrawal above the balance → **409**
(`EstoqueInsuficienteException`); negative quantities → **400**.

### Appointments — `/api/atendimentos`

| Method | Route | Description |
|--------|-------|-------------|
| `GET` | `/api/atendimentos` | List with filters |
| `GET` | `/api/atendimentos/{id}` | Full detail |
| `POST` | `/api/atendimentos` | Schedule (deducts stock) |
| `PUT` | `/api/atendimentos/{id}` | Update (only while `AGENDADO`) |
| `PATCH` | `/api/atendimentos/{id}/status` | Change status |

**`GET` filters** (all optional):

```
?status=AGENDADO        filter by status
?clienteId=<uuid>       filter by client
?dataInicio=<ISO>       lower bound (LocalDateTime)
?dataFim=<ISO>          upper bound (LocalDateTime)
```

**`POST` body:**

```json
{
  "clienteId": "0b6f...",
  "dataAtendimento": "2026-09-06T14:30:00",
  "servicos": [
    {
      "servicoId": "3f2a...",
      "itensExtras": [ { "itemId": "9c11...", "quantidade": 2 } ]
    }
  ]
}
```

Scheduling **deducts stock** automatically (service items + extras);
insufficient stock → **409**.

**`PATCH .../{id}/status` body:**

```json
{ "novoStatus": "CONCLUIDO" }
```

**Response (`GET /{id}`):**

```json
{
  "id": "a12c...",
  "clienteId": "0b6f...",
  "nomeCliente": "Maria Silva",
  "dataAtendimento": "2026-09-06T14:30:00",
  "dataCriacao": "2026-09-06",
  "status": "AGENDADO",
  "valorTotal": 170.00,
  "servicos": [
    {
      "servicoId": "3f2a...",
      "nomeServico": "Limpeza de Pele",
      "valorCobrado": 150.00,
      "itensUsados": [ { "itemId": "9c11...", "nomeItem": "Ácido Hialurônico", "quantidadeUsada": 2 } ]
    }
  ]
}
```

Listing returns the summary shape: `id`, `nomeCliente`, `dataAtendimento`,
`status`, `valorTotal`.

### Status transition rules

```
AGENDADO ──► CONCLUIDO
AGENDADO ──► CANCELADO   (returns the deducted stock)
CONCLUIDO ──► CANCELADO  (typo fix; does NOT return stock)
CANCELADO ──► (terminal state, immutable)
```

- Setting the current status → **409**.
- `PUT /{id}` is only allowed for `AGENDADO` appointments → otherwise **409**.

## Error handling

All failures share a consistent shape:

```json
{
  "status": 404,
  "mensagem": "Recurso não encontrado",
  "erros": []
}
```

| HTTP | Cause |
|------|-------|
| `400` | Field validation, malformed JSON, wrong query-param type |
| `404` | Missing resource |
| `409` | Conflict: duplicate, insufficient stock, invalid status transition, resource in use |

Mappings live in [`GlobalExceptionHandler`](src/main/java/com/cliniva/exception/GlobalExceptionHandler.java).
